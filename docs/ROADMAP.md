# 開發階段、驗證與完成條件

此檔定義工作與 gate，不記錄即時進度；實際完成情況看 `STATUS.md`。

## 1. 共通完成規則

- 每階段可獨立驗證，不等完整遊戲才測試。
- 測試報告分 PASS／FAIL／未測，附命令工作目錄、版本、環境與結果。
- build成功不代表透明、物理或效能通過；Linux不替代Windows原生驗收。
- 發現環境問題先排除；確認是程式缺陷就記錄重現及修正，不跳過必要檢查。
- 套件及工具鏈只在實際安裝／驗證後固定；不以研究表格當已相容。
- 進度與決策更新到STATUS，設計調整更新到DESIGN。不得只在聊天留下交接資訊。

## 2. Phase 0：技術可行性

**目標**：證明Windows透明＋Canvas＋Planck＋固定步進及量測可一起工作。

**工作／交付**：

1. 建立最小vanilla TypeScript／Vite／Tauri專案，固定通過的Node、Rust、npm依賴及lockfiles。
2. 260×420透明無框無陰影視窗，HTML／Canvas清底。
3. 獨立拖曳區、可見關閉入口、最小化，不加入真正隱藏／系統匣／全域快捷鍵。
4. 6～10固定釘、封閉外框、一顆自由落球及重新掉落控制，真正Planck碰撞。
5. 固定60Hz、DPR、暫停恢復、FPS／frame／physics step量測；比較120Hz及noRedirectionBitmap。
6. Windows release原型及 `docs/validation/phase-0.md`，含明確通過／失敗／未測證據。

**排除**：投注、倍率、完整軌道、80釘盤、12球道、系統匣、全域快捷鍵、完整遊戲UI。能在瀏覽器展示不等於此階段完成。

**依賴**：Windows x64建置／驗收資源、C++ Build Tools／Windows SDK、Rust MSVC、WebView2。Linux可先完成獨立工作；沒有Windows時此gate保留未通過。

**驗收**：Win10／Win11桌面真正透視、無異常背景／邊框／殘影、實際碰釘、DPI清楚且不改物理、拖曳／最小化／關閉正常、恢復不追算、release達第8節效能目標。

**主要風險**：DWM／WebView2／GPU合成、閃白、依賴相容、缺Windows資源。合理修正後仍重大失敗才按DESIGN比較Electron，不直接擴功能掩蓋問題。

## 3. Phase 1：完整物理球盤

**依賴**：Phase0通過；若只做跨平台可獨立工作，必須明確保留Windows gate，不稱整體完成。

**工作／交付**：版本化外框與釘位、槽底起球、側軌及頂部導流、滑鼠／鍵盤力道、弱發射重發、12隔板／sensor、安全落點、卡球／出界、無畫面harness。交付物理測試盤與可重現輸入集，不加投注倍率。

**驗收**：

- 重力、碰釘、阻隔、沿實體軌道入盤、不同速度改運動、同時一顆球。
- 弱發射返回後可重發，沒有傳送出口。
- 12格分別直接投球測判定，再以真正槽底發射驗證完整路徑，不能互相替代。
- 邊界／彈回／高速漏報處理可靠，結果一次。
- 預定有效力道至少1000次初步批次，正常、弱發射、重試、作廢分列；無未解釋穿透／出界／永久卡死。
- 自然可達球道與分布如實記錄，不強迫每格等機率或用外力達成。

**主要風險**：導軌接縫、過頂、釘頂平衡、隔板卡球、sensor漏報。先修尺度／幾何，再調步長／求解。

## 4. Phase 2：核心遊戲規則

**依賴**：可靠物理落點／返回事件。

**工作／交付**：純狀態轉移、餘額、投入、跑燈與呈現快照、停燈、seeded燈位、加碼、投注鎖定、一次結算、結果／下一局、餘額耗盡重開、技術作廢退款、最少UI。

**驗收**：倍率／燈數表正確、1～99與餘額限制、未停不能射、已射不能加碼、重發仍鎖定／不扣款／不重抽、重複／舊事件不生效；50／10／6得到100或40、最高獎990；下一局清理正常，暫停不改餘額／燈位。

**主要風險**：停燈顯示不同步、按鍵雙觸發、重發開回BETTING、退款與發獎重複。以規則單元與跨模組事件測試阻擋。

## 5. Phase 3：桌面使用體驗

**依賴**：回合及暫停語意穩定；基本拖曳／關閉／最小化在Phase0先完成。

**工作／交付**：系統匣、真正隱藏／恢復、可選置頂、快捷鍵設定／停用／衝突、DPI／多螢幕、休眠／原生拖動生命週期、簡短操作說明。

**驗收**：各phase重複隱藏恢復保留球與狀態，不追算／不重複結算；快捷鍵失敗能改由匣恢復，無可靠入口不能藏失聯；視窗及匣皆可退出，解除原生資源；跨DPI可操作。

**主要風險**：事件不同步、暫停原因互相誤清、失焦蓄力未取消、視窗藏失聯。

## 6. Phase 4：物理調校及效能

**依賴**：前階段可運行與可重現基準。效能從Phase0開始量測，不等此時。

**工作／交付**：版本化重力／材質／力道／釘位、60／120Hz與CCD對照、必要繪製優化、獨立種子的批次工具、分布／異常／效能報告。

**驗收**：初期1000次後定案布局至少10000次固定樣本；記力道分層、版本、seed、次數與無效樣本，無未處理卡死／重複結果。透明Windows release達標；分布不要求均勻，不追固定RTP，不刪壞樣本宣稱零異常。

**主要風險**：過擬合單seed、為均勻暗改球路、只看平均FPS、強硬體掩蓋問題。

## 7. Phase 5：正式打包

**依賴**：核心驗收通過、工具版本凍結、Windows原生release環境。

**工作／交付**：先Windows x64 NSIS單一格式、WebView2有／無情境、封裝資源、正常退出／卸載、使用說明、版本／雜湊／已知限制。MSI、ARM64、自動更新非首版。

**驗收**：乾淨Windows沒有Node／Rust／Vite仍可安裝、啟動、完成一局與退出；遊戲不依賴網路或dev server。若要求安裝也離線，選含官方WebView2安裝來源的模式，下載bootstrapper不能稱離線。測封裝版本，不以dev通過替代。

**主要風險**：Runtime缺少、產物路徑、DPI差異。公開散布時再決定簽章／憑證；未簽或未測不可稱已正式發布。

## 8. 測試策略與效能門檻

使用單一輕量TypeScript runner，優先評估Vitest，不另建服務；測試工具版本也要驗證。預計npm ci、型別檢查、單次測試、前端build及Tauri build，正式名稱待實作建立，**目前不是已存在或已驗證指令**。

| 層級 | 必要案例 |
| --- | --- |
| 設定 | 合法倍率、燈數、12格、不重複、seed重現、非法數值 |
| 投入／餘額 | 0／1／99／100、超餘額、+10超界、NaN／小數、安全整數、總餘額>99 |
| 跑燈 | interval邊界、掉幀、最近已繪倍率、重複停燈不重抽、暫停 |
| 狀態 | 未停不能射、已射不能加碼、重發鎖定、一球、下一局、零餘額 |
| 結算 | win／loss／void、50／10／6、99／10、重複／舊事件、退款不再獎 |
| 物理 | 重力、單釘反彈、初速、最高速度對釘／牆／隔板 |
| 球道 | 12格、隔板頂端、雙候選、彈回、高速跨sensor、穩定確認、一次結果 |
| 軌道／異常 | 真實沿軌、弱發射／重發、卡球、出界、非有限、逾時 |
| 時間 | 固定60／120Hz、截斷delta、追趕上限、丟時間記錄、插值、恢復 |
| 公平介面 | 相同物理輸入只改倍率／燈位，軌跡與落點不變 |

物理用固定tick和明確終止條件，不用wall-clock sleep；位置合理容差，固定runtime可重現，不要求跨平台bitwise一致。不自動重寫期望掩蓋碰撞失效。

建議效能門檻（Phase0校準，非已達成）：60Hz螢幕、可見、release、DevTools關，暖機10秒後至少120秒，含多次落球／碰撞。

| 指標 | 初始門檻 |
| --- | --- |
| 平均FPS | >=59，容許59.94Hz及計時誤差 |
| Frame interval p95 | <=20ms |
| >33.3ms的幀 | <=1% |
| Physics step p95 | 初始預算<=2ms |
| 追趕上限／丟時間 | 正常場景不持續觸發 |

記p50/p95/p99、draw time、CPU／GPU／driver／RAM、OS build、刷新率、DPI、WebView2及依賴版本。120／144Hz另記實際更新；低於60Hz螢幕不驗證60FPS。非透明版僅診斷對照，最後透明版通過。

## 9. Windows 手動驗收程序

1. 記環境。至少Win10 22H2及可用目標Win11；缺哪個標未測，不推定相容。
2. 深／淺桌布、其他程式、高對比格背景逐一置後，確認透視、抗鋸齒、無背景／邊框／殘影。截圖只能靜態證據，閃白用目視／錄影。
3. 冷暖啟動各至少10次，noRedirectionBitmap開／關比較，記差異才定案。
4. 100／125／150%與跨螢幕測清晰、hit target、拉桿、logical size；不得改物理狀態。
5. 各phase最小化／恢復，Phase3後真正隱藏／恢復，各至少10次；無跳位／倍率偷跑／重複入帳。
6. 拉桿出區、pointer取消、長按、失焦、Alt+F4、系統匣退出、快捷鍵衝突，無誤射／失聯。
7. 第8節效能測量，另做較長連續發射與視窗切換，記異常／記憶體趨勢。
8. Phase2後測中獎／失敗、上限、零餘額、弱射、測試模式卡球退款。
9. Phase5乾淨機安裝、有／無WebView2、離線遊戲、完整一局、卸載。

## 10. 未來驗證報告格式

實測時才建立 `docs/validation/phase-N.md`，不先放假結果。至少包含：

- 測試日期、程式commit／配置版本、工具與機器資訊。
- 工作目錄、確切命令／手動程序。
- 預期、實際、PASS／FAIL／未測；測試數、跳過數及原因。
- 對應的log／量測產物或截圖路徑。
- 限制、缺陷與下一個診斷步驟。

零測試、PID或port不能當功能證據；未解釋必要檢查失敗就不勾該gate。
