設定 schema 的實際驗證程序（Python 的 `jsonschema`）：

```python
import copy, json
from pathlib import Path
from jsonschema import validate
schema = json.loads(Path('node_modules/@tauri-apps/cli/config.schema.json').read_text())

validate(base, schema)
merged = copy.deepcopy(base)
merged['app']['windows'] = json.loads(Path('src-tauri/tauri.nrb.conf.json').read_text())['app']['windows']
validate(merged, schema)
```

### 單元與瀏覽器覆蓋

- 物理 9 案例：60／120 Hz 自由落下、實際碰釘與橫向偏移；各至少 30 秒固定 tick 不出封閉框；20 次重落始終一球；固定輸入可重現、快照隔離；拒絕不合法 dt。
- 時間 7 案例：30／60／144 Hz 畫面輸入都產生正確 60／120 步；長 delta 的 5／10 步上限、丟時間與餘數；多原因暫停不互解鎖；恢復不追算且同步插值；切換 Hz 不重建球；非法輸入。
- DPR／統計 6 案例：1／1.25／1.5／2 DPR 的 backing store／logical size；零樣本不回報 FPS；百分位／慢幀／丟時間統計；環形緩衝有界。
- Chromium 四種 DPR：清底像素 Alpha=0、body 透明、尺寸正確且無溢出、量測預設隱藏、瀏覽器原生視窗按鈕停用、碰釘顯示、手動暫停／恢復、60／120 切換、重落、無 pageerror。
- Chromium DPR=1 另測完整量測流程：暖機、暫停取消、重新記錄、120 秒內兩次手動落球、JSON download 內容／樣本數。這些秒數來自 **Playwright 虛擬時鐘**，不是真實暖機或效能測量；虛擬 FPS／step time 不列為門檻證據。

## 7. Windows CI 圖示缺漏修正（2026-11-04）

第 1～6 節保留首次原型驗證歷史；其中 Windows 工作流程「未測」是當時狀態。使用者隨後貼回 Windows CI 失敗日誌，沒有提供 run URL／來源 SHA，因此不推定具體 job 或 NRB 組別：

```text

`D:\a\Pinball\Pinball\src-tauri\icons/icon.ico` not found; required for generating a Windows Resource file during tauri-build
Process completed with exit code 1.
```

**失敗已確認**：專案缺少圖示資源。依 `Cargo.lock` checksum 核對並閱讀 `tauri-build 2.7.4` 的 `src/lib.rs`，Windows build script 會從 `bundle.icon` 選 ICO，未指定就找 `icons/icon.ico`，且不因 `bundle.active=false` 跳過。`tauri-codegen 2.7.4` 的 `src/context.rs` 在 Unix 另需 PNG，因此一起補齊。日誌中的 `package.metadata does not exist` 不是此次中止的主因。

**實際修正**：新增 `src-tauri/icons/icon.ico`（16／24／32／48／64／128／256 px）、`icon.png`（256×256 RGBA），於 `tauri.conf.json` 明確列出，並新增 Windows workflow 的 `Check native icon assets` 前置步驟。不修改遊戲規則、物理或套件版本；沒有安裝新的 npm／Cargo 依賴。
